# Paper pipeline rules

## Sources, publication and taxonomy

- Runtime Git push must preserve a caller-provided `GIT_SSH_COMMAND`, matching the other Git operations; otherwise use the existing secure defaults. Temporary DNS recovery must use a freshly verified address with the original host-key alias and strict host-key checking, never a permanent IP or disabled verification. Publication timeouts, process-group cleanup, pending receipts and exact remote confirmation remain mandatory.

- `routine_priority.check` 是历史回填只读准入真源，watch/worker/逐请求复用；任何例行最近一期回执未 completed/partial、暂停、待发布事务、云端采集无独立核验或下一检查点不足10分钟均让行。partial仍须原业务完整尝试与公开缺口，不由准入器伪造完成。云端核验回执在忽略的 `build/reports/collection-receipt.json`：schema_version=1、period（北京时间08/12/16的YYYY-MM-DDTHH:MM）、status=completed/partial、full_attempt=true、published=true、带时区verified_at、官方仓库actions run_url、evidence_path与evidence_sha256。证据必须在build/reports内，来自真实云端回执审计；URL或游标时间不能代替核验。不创建新采集器/定时器，不凭成功退出码补造回执。

- weekly_backfill读取私有backfill-control.json的resume_after（必须带时区）。暂停期间run/watch不得启动模型；在途任务在下一次admission停止领取，保留缓存/事务。恢复时间不影响daily、会议、模型或Stocks调度回执。

- 历史主题推理最多3次内容尝试；失败3次可保存skipped_trend（attempts、reason、failures、evidence_hash），全量逐篇contributions仍严格校验。只有证据绑定正确、trends为空的显式跳过记录可作为partial主题；日报默认生成不启用此降级。发布事务同时保留skipped_topics，远端核验前不推进。传输/环境/让行及文件故障继续传播，不计内容跳过。

- 主题趋势输出必须收敛：每条claim最多180字符、reasoning最多1200字符、limitations最多600字符；每条最多8个支撑引用且不超过当前论文数。所有论文及逐篇问题/贡献仍完整输入，引用ID枚举保持全量；限制输出篇幅和参考数量，不删减样本、不截断模型结果来通过验证。

- 主题趋势输出触及token上限时，在原3次尝试内将输出预算从6500依次提升至13000、20000；每次仍重查daily让行和共享推理预算，保留完整输入、引用schema及内容校验，不接受截断JSON，不将主题失败当少量论文跳过。其他传输故障保持原传播与断点恢复。

- Papercept官方程序页按URL数字fragment定位单篇；必须匹配同一viewAbstract编号的pTtl标题及Ab编号摘要块，不以整页标题或其他论文摘要替代。复用官方程序采集缓存时验证原URL回执哈希、精确论文身份，保留fragment与完整原文哈希；摘要仅提取Abstract标记之后正文，缺字段拒绝。

- SIGGRAPH官方日程仅支持config/conferences.yaml已确认的精确域名；单篇页以当前presentation-title核对身份，Description只作为official_description保存，不冒充official_abstract，不放宽跨域跳转。周报证据保留原文哈希、来源版本及basis；来源适配修复后复用成功逐篇缓存。

- 周报持续监督入口watch不直接生成或持有runtime锁；串行启动run子进程并等待退出，成功年份结束后退出，暂时失败或让行按60至900秒退避恢复。监督状态独立保存；子进程终止或监督退出不删除原事务、缓存和锁文件。Git网络命令可有限重试，真实冲突仍由原严格校验阻止发布。

- 期刊缺失证据按身份路由：arXiv ID使用arXiv采集器，conf-ID使用会议库记录与现有官方会议摘要采集器及其版本化缓存；官方摘要真源须绑定标题、来源URL、正文哈希、原始来源哈希和会议source_version。不能把会议ID传给arXiv接口。回填多线程共享的daily-request锁探测必须在进程内串行，避免探测线程互相误判成daily等待者。
- 主题趋势的paper_ids输出schema必须使用本主题本期真实ID枚举，禁止集合外引用；格式与语义校验失败最多3次本地模型重试，每次请求前重查让行。所有原始响应按内容哈希分别保留，不能通过删引用、改ID或放宽校验让错误分析通过。
- 期刊逐篇问题/贡献与主题趋势均通过本地模型生成；逐篇一次调用、最多4并发，共享持久化推理预算，缓存按证据哈希与提示词版本隔离。最近一周人工触发重生成也必须持有唯一runtime锁，退出时只关闭自己启动的模型服务。
- scheduler统一管理daily、stocks_weekly、stocks_actuals、models、conferences，保留旧论文回执兼容；stocks_weekly为周日08:00期次，stocks_actuals为每日00:00/08:00最近检查期次。无新证据也须核对待发布阶段后才结束。
- digests.py 从同一公开可见集合和已发布摘要生成论文日报/周报；每日构建同步更新 docs/reports/daily.html、weekly.html 与 periods/ 下受管日期 JSON。runtime 只允许这些精确路径进入每日提交，不能扩大到任意报告或 Stocks 输出。
- 日报每主题显示完整论文表和一句话问题/贡献；周报仅显示主题技术趋势、路线比较、局限与引用，不渲染逐篇列表/表格。周报仍使用全部论文证据，保留真源里的逐篇结果用于校验与复用。分析使用 content/papers/digests 真源并核验覆盖集合、摘要哈希及引用；过期或缺失分析明确标记待更新。
- daily arXiv 发布阶段先构建摘要，再在现有 runtime/model 锁内使用实际服务模型执行 digest_writer（最近8天及对应自然周，按证据哈希跳过已完成主题），最后重建发布；不额外启动协调器。分析失败保留旧真源、页面显示待更新，arXiv结果仍可发布但本期记partial并附 build/reports/digests/latest.json。自动提交仅允许 digests/ 下 daily/weekly-YYYY-MM-DD.json，不包含测试或私有回执。
- Public truth lives in content/papers/: archive.json (arXiv archive), arxiv-candidates.json (cursors/review decisions), paper-annotations.json (arXiv topics/tags/type/affiliations), conference-papers.json (official accepted lists), and conference-library.json (conference overlay/annotations). Private sources, model inputs/responses, caches and checkpoints remain under ignored build/.
- config/site.yaml alone defines topics, descriptions, aliases, tag dimensions and publication filters. New labels must not be hard-coded. site.py owns generated paper pages; rebuild docs/index.html, docs/search-index.json and affected notes/exports rather than hand-editing them.
- New candidates since collection.review_required_since require explicit acceptance before public lists/search/counts. Preserve previous review decisions and historical visibility; unknown/uncertain inference never authorizes deletion.
- Topic aliases preserve old URLs. Ordinary papers use publication year/month and day ranges 1-10, 11-20, 21-end; surveys use yearly Surveys tabs without counts. Search deduplicates multi-topic papers by arXiv ID.
- publication.excluded_years currently hides 2022/2023 from public lists/counts/search/conference summaries; retain source records, originals and notes. Verified older conference preprints may remain browsable, but this must not expose unrelated old arXiv archive entries.
- Paper tables show plain conference names without years/links in the Conference column. Preserve affiliation annotations privately/publicly as their existing schema allows; missing institutions display -. Never infer affiliation from author names.
- Tags describe technical methods, representations, conditioning and controls, not task/application/object types. Each topic needs at least three nonempty technical dimensions; use only the union of the paper's accepted-topic allowlists. Keep at most five tags, at most two per same-named dimension across the union, ordered by relevance.
- Surveys have no technical tags. Ordinary papers share a total two-round tag budget, including format repair and empty-tag review; valid empty tags publish normally and do not requeue. Source, topic and summary failures remain independent. Narrower annotations/AGENTS.md and summaries/AGENTS.md govern those modules.
- Publish pipeline changes with their affected public data and generated pages/search; never stage tests, caches, README or unrelated content.

## Runtime and scheduling

- 用户2026-10-25取消历史周报每周跳过论文篇数上限：可跳过明确的逐篇材料/输出失败，保留完整paper_ids与skipped_papers（标题、阶段、原因、当前证据哈希），仅基于成功论文生成趋势并显示覆盖缺口；全部论文均跳过的主题不生成趋势。全部主题处理并核实发布后记partial且推进更早周次，不冒充全量completed；跳过项不在主队列反复重试，证据变化使旧跳过失效。时间片让行、模型/锁/发布故障仍保留断点，不冒充逐篇失败。

- weekly_backfill 是显式授权的低优先级历史队列；每周获取runtime.lock并在周界释放，daily-request占用或新18:00边界时让行。公开写入仅限该周分析、核验官方摘要和周报生成产物，不提交其他任务改动；提交前复核HEAD和各受管文件初始状态，推送失败保存自己的pending SHA后停止，恢复先核实远端。每期必须通过全量validate_analysis，空周也保存明确分析。模型逐篇请求沿用digest_writer；大主题用全部逐篇问题/贡献综合，不依赖标题或截取部分论文。
- Root AGENTS.md owns business due times and Git boundaries; scheduler.py owns period/receipt semantics, and the saved sole automation owns its actual wake checkpoints. Follow ignored ops/RUNBOOK.md for machine paths/services; do not copy a second wake interval into rules or prompts.
- GitHub Actions only collects candidates at each configured slot, including intraday refresh. Keep completed shards/cursors and HTTP429 cooldown in the ledger; exhausted429 pauses the whole collection, preserves incomplete-topic cursors and returns a nonzero status. Do not use daily completion to skip later scheduled slots.
- Use the sole WSL entry bash ops/summary_runtime.sh daily. Publish/verify arXiv first. Conference backlog runs only Monday-Friday in 120-minute wall-clock slices, capped at the next18:00 arXiv boundary; finish the current paper, publish a validated checkpoint and release locks.
- Exit4 means an incomplete conference slice yielded: record deferred, not completed/partial. Resume only at a later authorized wake. A fully attempted eligible pass may be partial with failed/retry-held papers; keep retry_queues and remaining explicit. Weekend daily completes only its arXiv scope, retaining conference_deferred and conference-backlog-state.json.
- Save old daily conference baseline/attempts separately across periods so old conference work or failed publication recovery never skips the latest arXiv pass. Single-paper failure does not remove accepted membership or cause endless same-pass retries.
- One coordinator serializes daily, half-month model maintenance and weekly conference maintenance; each maintenance job validates, independently commits/pushes and confirms remote inclusion before handoff. Do not publish another job's unknown local commits.
- All model requests use the shared WSL/Linux runtime, model lock and persistent shared.inference_budget: cumulative7200s busy wall time, drain inflight requests, then600s rest. Concurrent calls do not multiply time; counts never trigger rest; restarting cannot reset the budget. Model default/capacity comes from model_runtime.py and the deployed service.
- Daily selection prioritizes unattempted work and rotates retries. Historical backfill holds runtime.lock for one100-paper checkpoint batch, publishes and releases it for waiting daily. Keep existing batch/cycle-state.json compatible; runtime's weekend name is only a backfill compatibility alias, not a conference schedule.
- Runtime Git pull/fetch/push use bounded waits and terminate only their own timed-out process groups. Recover a pending push only when HEAD matches pending-runtime-push.json. Never delete live lock files or kill an unrelated service/job.

## Explicit review and recovery
- Full rechecks use python -m papers recheck, numeric arXiv IDs deduplicated newest-first, existing runtime/public-write locks and a recoverable journal. Recheck itself never pushes. Delete only freshly rejected topic memberships; remove public membership only if all topics are rejected, preserving originals and uncertain decisions.
- User decisions outrank model relevance uncertainty. Record user-authorized acceptance/deletion explicitly; application-only medical/clinical/biomedical papers follow the existing exclusion decision. Do not repeat historical frozen review/deletion instructions as new work.
- Named runs use build/paper-summaries/recheck/runs/<run-name>/ and preserve previous runs. recheck/local-only.json disables automatic sync/publication until explicitly authorized; another job must not remove it or publish those local commits.
- Rechecks may fill missing summaries and replace annotations through source-backed validators. Strict recovery uses per-paper configured enums/JSON schema, never arbitrary malformed-JSON repair or widened tag allowlists. Recovery revisions invalidate only selected private inference receipts, not original queues or successful public results.
- Canonical per-topic recheck_decisions precede legacy selected_topic for batch consumers. Resume both unfinished and failed/uncertain IDs; compare round AND offset when judging progress.
- Topics-only review first restores identity-verified official abstracts; unavailable PDFs must not block that classification. Conference recheck uses checksum-verified official evidence and explicit all-false topic_review for retained hidden tombstones; intake cannot resurrect these.
- Operator-verified author abstracts or official conference descriptions are allowed only within their frozen recovery scope, with original URL/raw path/SHA256, digest verification on replay and title-version evidence. Distinguish descriptions from abstracts. Identity-verified introduction recovery is capped at18000 chars and marked when truncated.
- If line-break artifacts prevent copied quotations, the model may select numbered source spans: preserve exact span tables/selections, verify indices/taxonomy, derive quotations only from original spans. Empty selections after two rounds are valid; never manufacture tags.
- All new/modified tests and mocks stay under ignored build/, are verified then deleted, and never go to commits/cloud. Preserve review lists, sources, caches, checkpoints and publication receipts.

## Conference intake, evidence and retries
- proceedings.py owns config-driven official accepted-list collection and deterministic matching since2024. Never infer acceptance from topic, affiliation, submission or a fuzzy title score. Failed/pending editions preserve prior successful lists and evidence under build/conferences/.
- conference_library.py owns the public overlay; conference_intake.py owns newest-first screening/deduplication/summaries; conference_sources.py acquires restricted official evidence; conference_retry.py owns versioned failure routing; conference_evidence.py selects bounded body evidence and optional local OCR.
- Conference IDs never enter arXiv annotation catalogs. Store conference annotations on their library record using the same taxonomy/limits. Internal IDs derive from DOI/official URL; display IDs YYMM.DDXXX (XX for unknown components) are not arXiv IDs. Preserve actual arXiv IDs when verified.
- Title-only positive screening may publish a conference entry before its summary; ambiguous titles remain pending. screen --apply imports only positive reviews. Preserve explicit arXiv-ID/normalized-title rejections, source evidence and human exclusions.
- Deduplicate against the arXiv archive/ledger, enriching rather than restoring reviewed-away entries. Summary/annotation failures never erase accepted records or older successful results; publish stages independently.
- Shared runtime and public-write locks protect intake. review uses the configured title model; summarize --limit 20 is an operational slice; --all attempts eligible work once, not endless retries. Scheduling/weekday/deadline admission belongs to the daily runtime/sole coordinator. Interrupted weekly slices persist attempted IDs and resume with remaining budget plus repeated --exclude-id; exclusions do not consume the new attempt limit.
- Official alternatives come from existing record.conferences URLs or identity-verified page links. Keep HTTPS/host, redirect, size and exact identity checks; never fabricate body text from titles or broaden the separate arXiv acquisition contract.
- Summaries may use verified Introduction, Overview/Motivation or actual body excerpts when standard headings/abstracts are absent. Keep missing abstract missing; do not label arbitrary body as official abstract/Introduction. Abstract/navigation/reference-only pages cannot generate body summaries.
- Record source URL, raw/selected checksums, sections, material basis, extraction method and truncation. Keep raw selected evidence/optional OCR under build/conferences/intake/; public provenance contains no private path. Local bounded OCR still requires identity checks; missing tools remain material failures.
- Annotation may independently use a verified official abstract when full text fails, or an explicitly labeled verified body excerpt when no abstract exists. Preserve successful summary and annotation separately; explicit evidence and constrained annotation modes use separate cache keys.
- Retry queues are network/material/identity/adapter/annotation. New work wins. Requests allow at most three attempts, each supervised in WSL with a hard120s cutoff.429 and503 with Retry-After set official-host cooldown; paper backoff1/3/7days must never be earlier than that deadline. Material/adapter and403/404 failures recheck after7days.
- Identity conflicts remain isolated until source/recovery version changes or a documented reviewed release. Source/recovery changes allow one new attempt even for an older attempted ID. Snapshot legacy receipts before migration and keep attempts/baselines; never repeatedly reset counters.
- Reparse verified cache before fetching. Due failures refresh full text AND independent abstract sources; archive changed bytes/verified receipts by hash. retry-status is read-only; retry-release requires a specific ID and review reason, preserving an audit receipt. Worker/crash/checkpoint infrastructure failures stop the job.
- Proceedings refresh revalidates cached lists with validators/hashes. Public source versions bind one selected edition to acquisition identity; other editions update only provenance. Identity/version changes mark summary/annotation pending refresh, retaining successes until replacements pass. Initial baselines skip refresh only when title, URL and supplied DOI/arXiv identity match; changed versions use separate private caches.
- summarize --skip-failed can exclude previous failures for explicitly scoped historical work; keep their receipts/evidence. Per-paper acquisition/inference exceptions remain retryable; interrupts, memory exhaustion and checkpoint-write failure are fatal.

## Conference dates
- config/conferences.yaml retains official sources/verification dates for actual editions, including history/future. Timeline shows current year plus preceding two years; pending publication stays pending and biennial meetings never invent off-years.
- conference_dates.py resolves missing dates newest-first: verified arXiv first submission, then official/DOI/publisher evidence. Never substitute revision, retrieval, conference date or inferred display-ID prefix for paper publication.
- Exact normalized title must identify a unique result. Fuzzy candidates require corroborating authors, DOI or verified official links; retain conflicting numbers/negations and reject competing plausible matches. A similarity score alone cannot merge records or change identities.
- conference_fuzzy.py ranks variants; conference_discovery.py discovers official/IEEE/GitHub metadata. Cached discovery is title-bound; Github README citations remain candidates, and creation/commit times are not publication dates. Retain actual author/source evidence URLs; GitHub limits halt that source while independent lookups continue.
- python -m papers.conference_dates --fuzzy --apply supports --arxiv-only/--web-only. Resume an interrupted applied web pass in the same maintenance period with --fuzzy --web-only --resume --apply: reuse receipts/failures, re-query changed titles and unattempted IDs, and revalidate against all candidates. --refresh overrides resume for a fresh weekly check.
- Date lookup is independent of full-text/summary success and never writes body summaries. Keep stable library IDs, human decisions and previous values on failure. Dry runs cannot mark unapplied values applied. Save provenance publicly and candidate/request/retry reports under build/conferences/dates/; honor arXiv spacing/429 backoff.
- conference_web_dates.py is the explicit webpage fallback after scholarly/arXiv/fuzzy lookup: verify title, retain raw evidence, allow page publication/modification metadata, paper schedule, explicit page-generation date or HTTP Last-Modified, and label webpage_* separately in UI. Never use HTTP Date, fetch time, GitHub commit time or invented components. Scholarly evidence takes precedence.
